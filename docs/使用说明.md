# Codex 续航使用说明

## 运行要求

Windows 10/11 x64，已安装 .NET Framework 4.8。无需 Node.js、Python、独立数据库服务或单独的 OpenAI API Key。

解压便携包后双击 `CodexAutoContinue.exe`。程序以当前 Windows 用户运行，不需要管理员权限。

## 首次使用

1. 启动 Codex 桌面端，再启动本程序。主面板读取最近 120 个未归档的本机桌面主会话。
2. 打开“连接与应用”，检查 Codex 数据目录（默认 `%USERPROFILE%\.codex`）。CLI 默认自动查找，也可指定 `codex.exe` 的完整路径。
3. 为需要观察的会话打开右侧监控开关。单会话默认关闭；全局暂停会暂停所有自动发送。
4. “重试策略”中选择中文 `继续`、英文 `continue` 或自定义内容。点击保存后生效，手动与自动续接共用设置。
5. 关闭窗口默认缩小到系统托盘，继续监控。托盘菜单“退出”会结束程序。开机启动需要在设置中主动开启。

“打开数据目录”可以查看本程序自己的数据：`%LOCALAPPDATA%\CodexAutoContinue`。其中 `monitor.db` 保存监控开关、异常次数和事件；`settings.json` 保存设置，完整 Webhook URL 与签名密钥使用当前 Windows 用户的 DPAPI 加密。

## 会话状态与续接

程序只读 Codex 自己维护的 SQLite 事件投影，不修改 Codex 数据库或认证信息。首次启动先建立基线：历史 `inProgress` 记录可能已经离线或正在等待，因此显示“状态待确认”，启动前的失败不会自动重发。

只有本次监测后新确认的、可归类为网络或临时服务故障的终态失败，才进入续接计划。默认等待 30、60、120、240、300 秒，每次异常最多续接 5 次。每次发送前重新读取目标会话，确认仍是原失败轮次。新任务、主动停止、完成、缺失会话、数据源变化或不可读取状态都会取消旧计划。

内部重试不重复发送。鉴权、余额、上下文窗口、未知错误以及没有可靠重置时间的额度或速率限制转为人工关注。程序不会猜测额度恢复时间。

续接使用现有认证的 Codex CLI：

```powershell
codex queue --thread <会话ID> --message "继续" --resume
```

发送前会持久化投递意图。CLI 接受请求、返回成功或消息进入队列，都只会显示“待确认”。只有同一会话的新轮次产生实际输出、工具执行进展或成功完成，才确认恢复。无法确认的投递不会自动再发；重启也保留这一保护。程序关闭期间已成功结束的新轮次，可以通过真实结束时间核对恢复。

## 当前桌面端接入限制

**本机已验证真实会话读取，尚未验证桌面端自动恢复成功。** 当前 Codex 桌面后端以 stdio 运行，没有发现可供外部程序连接的现有控制端点。CLI 的 `--resume` 可能提示恢复失败，但仍返回退出码 0，消息也可能已经入队。

遇到“消息可能已入队，但桌面恢复请求未确认”时，需要到 Codex 核对。程序会保持待确认，不会重复填入消息。这个测试版不能保证当前所有 Windows Codex 桌面版本均能无人值守恢复。它不会启动另一个 app-server 并把其历史状态冒充桌面实时状态，也不会通过盲目模拟键盘发送消息。

## Webhook 通知

在“通知设置”选择钉钉、飞书、企业微信或通用 Webhook，填写 HTTPS 地址。钉钉与飞书可填写签名密钥。机器人如果启用了关键词规则，应允许 `Codex Auto Continue`。

“测试通知”会立即向输入的地址发送一条真实测试消息；它不保存未提交的设置。开启通知并保存后，异常、确认恢复和重试耗尽按所选事件投递。通知含会话标题/ID、脱敏原因、次数和时间，不发送完整对话、提示词或命令输出。通用 Webhook 接收 JSON，字段为 `source`、`eventType`、`title`、`threadId`、`state`、`reason`、`attempts`、`nextRetryUtc`、`timestampUtc`。

通知最多重试 3 次，与会话续接独立。平台返回 HTTP 200 但业务错误码非零仍视为失败。更换接收地址或平台会取消尚未完成的旧通知，避免发往新的目标。关闭通知会停止新的投递；已在网络传输中的请求无法撤回。

## 从源码构建

安装 .NET SDK 与 .NET Framework 4.8 Developer Pack，在仓库根目录运行：

```powershell
.\build.ps1
```

脚本执行 Release x64 构建和行为测试，在 `dist` 中生成 EXE 便携目录与 ZIP。SQLite 使用 Windows 10/11 自带的 `winsqlite3.dll`，不需要额外安装原生 DLL。

仅执行桌面启动检查：

```powershell
.\src\CodexAutoContinue\bin\Release\net48\CodexAutoContinue.exe --smoke-test
```

项目目前没有代码签名证书；请从本项目构建或核对发布包的 SHA-256。
