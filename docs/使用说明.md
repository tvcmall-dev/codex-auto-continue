# Codex 续航使用说明

适用版本：`0.2.1-preview`。

## 运行要求

Windows 10/11 x64，已安装 .NET Framework 4.8。无需 Node.js、Python、独立数据库服务或单独的 OpenAI API Key。

解压便携包后双击 `CodexAutoContinue.exe`。程序以当前 Windows 用户运行，不需要管理员权限。

## 首次使用

1. 启动 Codex 桌面端，再启动本程序。主面板读取最近 120 个未归档的本机桌面主会话，默认显示“执行中”；切换“全部”可查看其他状态的会话，也可选择“需关注”。
2. 打开“连接与应用”，检查 Codex 数据目录（默认 `%USERPROFILE%\.codex`）。CLI 默认自动查找，也可指定 `codex.exe` 的完整路径。
3. 为需要观察的会话打开右侧监控开关。单会话默认关闭；全局暂停会暂停所有自动发送。
4. “重试与消息”中选择中文 `继续`、英文 `continue` 或自定义内容。点击保存后生效，手动与自动续接共用设置。
5. 关闭窗口默认缩小到系统托盘，继续监控。托盘菜单“退出”会结束程序。开机启动需要在设置中主动开启。
6. “应用升级”中可查看当前版本、可用版本、下载进度及安装状态。默认自动检查、下载和空闲安装，也默认接收预览版。

“打开数据目录”可以查看本程序自己的数据：`%LOCALAPPDATA%\CodexAutoContinue`。其中 `monitor.db` 保存监控开关、异常次数和事件；`settings.json` 保存设置，完整 Webhook URL 与签名密钥使用当前 Windows 用户的 DPAPI 加密。

## 会话状态与续接

程序只读 Codex 自己维护的 SQLite 事件投影，不修改 Codex 数据库或认证信息。首次启动先建立基线，启动前的失败不会自动重发。仅有历史 `inProgress` 记录时，会话可能已离线或正在等待，程序显示“状态待确认”。

首次读取时，如果同一轮次仍为 `inProgress`，且最近 2 分钟内有真实助手输出或已完成的工具执行，列表可立即显示“执行中”。**这只用于展示近期活动线索，不用于确认自动续接成功。** 尚未完成的工具调用和轮次开始记录本身不算执行证据；超过 2 分钟没有新执行证据仍会转为待确认，不自动触发续接。

`0.2.1-preview` 同时修复了状态显示延迟：同轮用户消息的时间可能精确到毫秒，而轮次开始时间只精确到秒，读取时会正确处理这两种精度，避免开始事件被误当作旧事件过滤。新轮次可在下一次轮询显示“执行中”，无需等待首条输出。详情面板复用本轮数据，并合并重复刷新，减少历史事件较多时的界面卡顿。

只有本次监测后新确认的、可归类为网络或临时服务故障的终态失败，才进入续接计划。默认等待 30、60、120、240、300 秒，每次异常最多续接 5 次。每次发送前重新读取目标会话，确认仍是原失败轮次。新任务、主动停止、完成、缺失会话、数据源变化或不可读取状态都会取消旧计划。

内部重试不重复发送。鉴权、余额、上下文窗口、未知错误以及没有可靠重置时间的额度或速率限制转为人工关注。程序不会猜测额度恢复时间。

续接使用现有认证的 Codex CLI：

```powershell
codex queue --thread <会话ID> --message "继续" --resume
```

发送前会持久化投递意图。CLI 接受请求、返回成功或消息进入队列，都只会显示“待确认”。只有同一会话的新轮次产生实际输出、工具执行进展或成功完成，才确认恢复。无法确认的投递不会自动再发；重启也保留这一保护。程序关闭期间已成功结束的新轮次，可以通过真实结束时间核对恢复。

## 当前桌面端接入限制

**本机已验证真实会话读取，尚未验证桌面端自动恢复成功。** 当前 Codex 桌面后端以 stdio 运行，没有发现可供外部程序连接的现有控制端点。CLI 的 `--resume` 可能提示恢复失败，但仍返回退出码 0，消息也可能已经入队。

遇到“消息可能已入队，但桌面恢复请求未确认”时，需要到 Codex 核对。程序会保持待确认，不会重复填入消息。这个测试版不能保证当前所有 Windows Codex 桌面版本均能无人值守恢复。它不会启动另一个 app-server 并把其历史状态冒充桌面实时状态，也不会通过盲目模拟键盘发送消息。

## Webhook 通知

在“通知设置”选择钉钉、飞书、企业微信或通用 Webhook，填写 HTTPS 地址。钉钉与飞书可填写签名密钥。机器人如果启用了关键词规则，应允许 `Codex Auto Continue`。

“测试通知”会立即向输入的地址发送一条真实测试消息；它不保存未提交的设置。开启通知并保存后，异常、确认恢复和重试耗尽按所选事件投递。通知含会话标题/ID、脱敏原因、次数和时间，不发送完整对话、提示词或命令输出。通用 Webhook 接收 JSON，字段为 `source`、`eventType`、`title`、`threadId`、`state`、`reason`、`attempts`、`nextRetryUtc`、`timestampUtc`。

通知最多重试 3 次，与会话续接独立。平台返回 HTTP 200 但业务错误码非零仍视为失败。更换接收地址或平台会取消尚未完成的旧通知，避免发往新的目标。关闭通知会停止新的投递；已在网络传输中的请求无法撤回。

## 自动升级

### 从旧版本升级

**0.1.0-preview 没有自动升级功能，必须先手动安装当前版本一次。** 从托盘退出旧程序，在[本项目发布页](https://github.com/tvcmall-dev/codex-auto-continue/releases/tag/v0.2.1-preview)下载 `0.2.1-preview` 便携包或 EXE，核对 SHA-256 后覆盖原目录，再运行 `CodexAutoContinue.exe`。不要更改这个文件名，后续自动升级会按此名称替换程序。0.2.0-preview 用户可在“应用升级”中检查并安装本版。

设置与监控数据位于 `%LOCALAPPDATA%\CodexAutoContinue`，不在程序替换范围内。请将便携包放在当前用户可写的目录；自动升级不会请求管理员权限。

### 检查、下载与设置

程序默认在启动时检查一次，随后每 6 小时检查一次。更新来源固定为 [GitHub Releases · tvcmall-dev/codex-auto-continue](https://github.com/tvcmall-dev/codex-auto-continue/releases)，不会接受自定义更新地址，也不需要 GitHub 令牌。发现较新版本后自动下载本项目的 `CodexAutoContinue.exe`，校验 SHA-256、文件大小和程序版本，校验通过才进入等待安装状态。下载缓存位于用户数据目录的 `updates` 子目录。

在“设置 → 应用升级”中可以调整以下选项，点击“保存设置”后生效：

- “启动时自动检查，此后每 6 小时检查一次”：关闭后停止定期检查；仍可点击“立即检查更新”，手动检查也会下载可用版本。
- “下载完成后，在程序空闲时自动重启安装”：关闭后保留手动安装入口。想完全手动控制时，同时关闭自动检查和自动安装。
- “接收预览版更新”：默认开启。关闭后只选择正式版，版本判断使用语义化版本，不会自动降级。

“立即检查更新”使用已保存的通道设置。“保存设置并重启安装”会先保存设置并关闭设置窗口，再尝试安装已校验的版本；活动任务尚未结束时仍会等待。网络失败或 GitHub 限流只会更新升级状态，不中断会话监控。修复网络或目录权限后可手动重试。

### 什么情况下会等待安装

升级不会在以下操作进行时重启本程序：

- 设置窗口仍打开，或正在刷新会话、保存设置、发送续接消息。
- 正在投递通知或发送 Webhook 测试消息。
- 全局监控与该会话监控均已开启，并且仍有自动续接计划；即使计划还没有到执行时间，也会延迟安装，直至计划完成或被取消。

安装前保存监控状态，暂时阻止新的操作，然后由独立更新进程等待旧程序退出、替换 EXE 并重新启动。待确认的投递状态会保留，重启后继续核对实际执行证据；不会仅因升级而重复发送。原先缩到托盘的程序会在升级后恢复到托盘。

### 启动检查与故障恢复

替换时在程序目录保留 `CodexAutoContinue.exe.previous` 作为上一版本备份。新进程需在 20 秒内完成初始化并返回启动检查回执；提前退出或超时会触发回退，随后尝试重新运行上一版本。失败版本在 24 小时内不再自动下载安装，可在处理故障后通过手动检查重试。

如果目录权限、文件占用等问题使替换或回退无法完成，升级状态会提示失败。先从托盘退出所有本程序实例，再确认 EXE 所在目录可写。若原 EXE 不可用且 `CodexAutoContinue.exe.previous` 仍存在，可将备份复制为 `CodexAutoContinue.exe`；也可重新下载并覆盖已知可用的发布包。用户数据目录中的 `settings.json` 与 `monitor.db` 会保留。

自动升级更新的是本辅助程序，不会改变前文所述 Codex 桌面端恢复控制接口的限制。

## 从源码构建

安装 .NET SDK 与 .NET Framework 4.8 Developer Pack，在仓库根目录运行：

```powershell
.\build.ps1
```

脚本默认构建 `0.2.1-preview`，执行 Release x64 构建和行为测试，在 `dist` 中生成 EXE 便携目录与 ZIP。也可用 `.\build.ps1 -Version 0.2.1-preview` 指定版本；脚本会将版本传入编译，并确认 EXE 的 `ProductVersion` 与包版本一致，随后生成 `SHA256SUMS.txt`。SQLite 使用 Windows 10/11 自带的 `winsqlite3.dll`，不需要额外安装原生 DLL。

仅执行桌面启动检查：

```powershell
.\src\CodexAutoContinue\bin\Release\net48\CodexAutoContinue.exe --smoke-test
```

验证真实独立进程升级与失败回退（先退出本程序，再使用 64 位 Windows PowerShell 5.1）：

```powershell
powershell.exe -NoProfile -File .\tests\Verify-UpdateIntegration.ps1
```

脚本使用临时隔离安装与数据目录，检查程序启动回执、旧 EXE 备份、失败回退后的重启、24 小时冷却边界及设置与 SQLite 数据保留；仅清理本次创建的进程和临时目录。

项目目前没有代码签名证书；请从本项目构建或核对发布包的 SHA-256。
